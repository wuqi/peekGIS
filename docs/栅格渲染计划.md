# 栅格渲染计划

## 1. 目标与范围

为 peekGIS 增加 GDAL 栅格图层（GeoTIFF、HDF、NetCDF 等）的显示能力，与现有矢量流程统一：

- 支持**单 dataset**（单个栅格文件）与**多 dataset**(GDAL 多子数据集，如 HDF/H5/NetCDF 驱动暴露多个 subdataset)。
- 有 subdataset 的文件在**拖入时弹出选择界面**选择要加载的 dataset（与矢量多图层选择一致）。
- 栅格渲染三种模式：
  - **单波段拉伸**：灰度/拉伸显示，默认用数据集 min/max，提供可调整界面。
  - **伪彩色渲染**：单波段按颜色表(colortable 或自定义渐变)映射颜色。
  - **多波段彩色**：任选 3 个波段作 R/G/B(可重复)，四波段常见影像(A/IR/R/G)默认排序成自然色。

边界（本计划**不做**）：
- 金字塔/瓦片近实时渲染、动态重投影缓存、色带编辑器(仅内置少量预设渐变)。
- warp 到磁盘、全分辨率预览、地理配准编辑。

## 2. 架构现状与接入点

现有数据流（矢量）：
```
拖文件 -> main循环 pendingOpen -> loader.enqueue()
  层元数据预读(readLayerMetadata) -> 多图层则弹 UI 对话框选图层
  -> AsyncLoader worker 线程读 GDAL OGR 几何 -> ChunkEvent 流回主线程
  -> GLBackend.appendLayer(每帧增量) -> render() 用统一 program 画线/点/面
```

栅格需要完全不同的绘制与数据路径，但可复用：
- 文件打开对话框、拖入流程、同路径去重、`ui.openPaths/pendingOpen` 主循环调度。
- `ensureGdal()`/`gdalOpenVector`/`gdalKeeper` 的 GDAL 初始化与 dataset 复用模式。
- 图层面板 `MapLayer` 列表、右键菜单、显隐、`buildDockLayout` 布局。

### 关键差异
| 项 | 矢量 | 栅格 |
|---|---|---|
| 数据 | 几何顶点(VBO) | 像素纹理(TexImage2D) |
| 重投影 | CPU 重投影后 CPU→GPU | 纹理按地理范围四角画四边形 |
| 渲染程序 | 单一 `program`(VS+FS) | 新增 GLSL 采样程序(+相对色/伪彩色分支) |
| 层级 | OGR 图层 | GDAL dataset / band |

## 3. 数据结构

### `RasterData`（`src/data/raster_reader.h`）
```cpp
struct RasterBandInfo {
    std::string name;      // 波段名 / "Band 1"
    int index = 0;         // 1-based 波段号
    double min = 0, max = 0;
    bool hasMinMax = false;
};
struct RasterData {
    std::string name;
    std::string sourceCrs;      // 文本, 如 "EPSG:4326"
    int srcEpsg = 0;
    std::string geotransform;   // 或双精度数组 geo[6]
    double geo[6] = {0,0,0,0,0,0};
    int width = 0, height = 0;  // 像素尺寸
    double minx, miny, maxx, maxy;  // 地理范围(源 CRS)
    int bandCount = 0;
    std::vector<RasterBandInfo> bands;
    // 实际像素数据(栅格平面, 见 §4)由 worker 上传 GPU, 不常驻 CPU
};
```
- 单 dataset 对应一个 `RasterData`；多 dataset 文件每个 subdataset 对应一个 `RasterData`，用户选中的才加载。

### `MapLayer` 扩展（`src/map/map_scene.h`）
给 `MapLayer` 加一个区分类型的标记，以及栅格专用状态：
```cpp
enum class LayerKind { Vector, Raster };
// MapLayer 增加
LayerKind kind = LayerKind::Vector;
std::optional<RasterData> raster;      // 栅格图层数据(单 dataset 对应一个)
std::vector<RasterRenderOptions> rasterOpts; // 每个栅格子图层一套渲染选项(见 §5)
```
- `layers` 向量同时容纳矢量与栅格图层，UI 列表/右键菜单多数地方已按 `idx` 工作，改动小。
- 范围合并 `addLayer/expandExtent` 需对栅格也用 `minx..maxy`（与矢量相同逻辑，可复用）。

## 4. 导入与 dataset 解析

### 4.1 类型识别
- `main.cpp` 拖动/`open` 后，用 GDAL 探测是矢量还是栅格：
  - 先 `GDALIdentifyDriverEx(path)` 或者试开 `GDAL_OF_RASTER` 看是否成功。
  - 决定走矢量 `readLayerMetadata` 分支还是新建栅格分支。
- 扩展名提示仅作为快速分派（`.tif/.tiff/.img/.hdf/.nc/.vrt` → 栅格；`.shp/.gpkg/.gdb` → 矢量），失败回退探测。

### 4.2 subdataset 枚举
```
GDALOpenEx(path, GDAL_OF_RASTER)
  -> GetSubDatasets() 得到 "NAME: subdataset全名" 列表(m次)
     m==0  -> 单 dataset, 直接读主 dataset
     m>0   -> 每个 subdataset 用 GDALOpenEx(subName) 读它的 bands/尺寸
```
- 复用现有 `LayerMeta` 结构存 subdataset 列表（`name` = 子数据集全名，用于后续打开）。
- 后台线程预读（模拟 `readLayerMetadata`），完成后主线程弹选择对话框（复用 `ui.layerMeta/layerDialogPath/ui.showLayerDialog`——但需标记"这是栅格子数据集列表"）。

## 5. 渲染选项模型 `RasterRenderOptions`

每栅格**图层**一套（多 band 组合成影像的单图层只有一套；伪彩色也一套）。存于 UIState 或 MapLayer，供调整界面读写，改后触发重传纹理参数/重建着色。
```cpp
enum class RasterRenderMode { StretchGray, Pseudocolor, RGB };
struct RasterRenderOptions {
    RasterRenderMode mode = StretchGray;
    // --- 单波段/伪彩色应用波段 ---
    int grayBand   = 1;            // 拉伸/伪彩色用的波段(1-based)
    // --- 多波段 RGB ---
    int rBand = 1, gBand = 2, bBand = 3;  // 波段可重复
    // --- 拉伸 ---
    bool useAutoMinMax = true;     // 自动用数据集 min/max(默认)
    double minRaw = 0, maxRaw = 0; // 手动拉伸范围(关闭 auto 时生效)
    double gamma = 1.0;
    // --- 伪彩色 ---
    int colorMap = 0;              // 预设渐变索引(如 gray/thermal/topo/spectral)
    bool clipNoData = false;
};
```
- **默认值**：首次加载按 band 类型给默认——若只有 1 band → `StretchGray`；若有 `Palette` 颜色表 → `Pseudocolor`（用其表）；若 ≥3 band → `RGB`（取前 3 个非 alpha 的波段）。`useAutoMinMax=true`（符合"暂时先用默认最大最小值"）。

## 6. GPU 渲染与缓存贴图

### 6.0 分层缓存策略(重要)：底图 + 细节块 LRU
避免一次性全量解码，同时**保证任何 zoom/平移画面都不黑**。采用**双层**：

**第 1 层：底图（必须垫，保证不黑）**
- 整 dataset 缩成一张**固定比例**纹理(最长边 ≤1024，保持纵横比)。
- 以"世界范围→纹理"的四边形渲染。任何 zoom/pan 都先画它 → **永远有内容，不黑**。
- 因为纹理采样随 view 插值，缩放本身不闪烁；底图总是就绪。

**第 2 层：细节块（LRU 256×256，保证清晰）**
- 只对当前视口需要的 256×256 像素块做高分辨率读，作为独立小四边形叠加在底图上。
- 平移/缩放时枚举可见块：命中 LRU 就画，未命中置"待读"，异步读完上传。
- **LRU 淘汰**：保留最近 N 块(如 256)，超限淘汰最久未用的块并删除其纹理。淘汰只影响细节，底图照画 → 不黑。
- 从金字塔 overview 读块速度快(有 R 金字塔) ；无金字塔按块 `RasterIO`(只扫块内像素，也快)。

**为什么两层都能少一不可**
- 只有细节块无底图：当前 zoom 无比特图、或刚启动未读块时，画面是**黑的**(你指出的问题)。
- 只有底图无细节块：放大后永远模糊。
- 底图管"不黑"，块管"清晰"，两者独立，淘汰不影响底图。

| 数据集尺寸 (宽且高) | 策略 |
|---|---|
| 任意尺寸 | 底图必垫；细节块按 view 需要读(≤2048 的小图底图≈整图，块只在放大时才需要) |

- **框定**：maxDim>**2048** 启用细节块层；否则直接用底图原始精度，不拆块。
- **底图缩放语义**：最长边 ≤1024 保持纵横比(另一维等比，最短约 52)。2048×40000 长条 → 52×1024 ≈ 53K 像素，几毫秒。
- **GDAL 读出**：底图用 `RasterIO` 目标尺寸=底图尺寸重采样；细节块用 `RasterIO` 读该像素窗口(256×256)于金字塔层级。
- **拉伸 min/max 前置**：由 `GetRasterStatistics`/扫描在加载初确定，底图与所有块共用一套渲染参数 → 叠加无缝不跳变。
- 采样在**后台线程**，纹理上传在主线程(或更新机制)。

### 6.1 纹理上传
- **底图**：单张 `GL_TEXTURE_2D` RGBA。
- **细节块**：LRU map(块 key→纹理)。每块 `256×256` RGBA8；块 key 含 (level, tx, ty)。
- 单波段：灰阶/拉伸在**CPU 组装 RGBA** 时完成(用前置 min/max，double 精度，保 NDVI)。伪彩色按 `bandValue->colormap->rgba`。RGB：r/g/b 三波段归一化合成 RGBA。
- 渲染时 sampler2D 绑定活动纹理单元(TEXTURE0，仿 imgui opengl3 已验证方式)。

### 6.2 绘制四边形
- **底图**：单个四边形，四角=源 CRS 世界范围，采样全局底图纹理。先画。
- **细节块**：每个命中的块一个四边形，四角=该块的像素矩形世界范围，采样块纹理，叠加在底图上(后画的在上)。
- 与矢量共用 `uCenter/uInv` 把源 CRS 坐标映射到 NDC。
- 注意：栅格源 CRS 若与显示 CRS 不同，需与矢量同样的重投影。V1：若显示 CRS==源 CRS 直接按 geo 范围画；否则先用 OGR 把四角重投影后再画(不做逐像素 warp，边缘精度有误差，注明限制)。
- 程序：栅格 fragment shader 用 sampler2D 采样绑定纹理。在 `GLBackend::render` 中栅格图层**先于矢量**绘制(铺底)，矢量画在其上。

### 6.3 显隐/顺序
- render() 遍历 `scene.layers`，按 `kind` 分派：Raster → 画纹理四边形；Vector → 现有逻辑。
- 顶底顺序：raster 图层的 z 顺序由其在 `layers` 中位置决定，UI 拖拽排序沿用(若存在)。

## 7. UI 面板

新增一个**栅格图层设置窗口**（或并入图层面板的右键"栅格设置"），含：
1. **渲染模式**：`拉伸灰度 / 伪彩色 / RGB彩色`（单选）。
2. **波段区域**（随模式变化）：
   - 拉伸/伪彩色：`波段:` 下拉(列出 `RasterData.bands`)，选单波段。
   - RGB：`R / G / B` 三个下拉(波段可重复)。
3. **拉伸调整**：`自动 min/max` 勾选；取消后出现 `min`、`max` 输入框(手动)；`gamma` 滑条。
4. **伪彩色**：`色带:` 下拉(内置几个预设)、`NoData 透明` 勾选。
5. 预览效果即时反映（改选项 → 重启纹理组装/上传）。

- 复用 dock：作为独立可开关面板(对标 `showAttributesPanel`)，或做成图层面板右键菜单打开的小窗。计划采用**图层面板右键 → "栅格设置"** 打开浮动小窗，避免再占 dock 空间。

## 9. 风险与决策点
- **高位深/大影像**：已由 §6.0 缓存策略解决——无金字塔且任一维 >2048 的先贴最长边 1024 缓存，实际读入 GF/GB 级影像也只上传最终纹理；显存占用 = 纹理 RW*RH*4*4B*(图层数)。带金字塔直接读实际；极端长条(如 2048×40000)由缓存"最短也缩到 ≤1024"兜底，不会撑爆。
- **波段可重复**：RGB 合成在 CPU 端把同一 band 归一化写进 R/G/B 通道即可，天然支持，无需额外处理。✔
- **伪彩色 color table**：GDAL `GetColorInterpretation()==Palette` 时读 `GetColorTable()`；否则内置渐变。两种都映射到同一 `bandValue->rgba` 函数。
- **重投影精度**：直接画四角锚点 + 纹理采样，远离源 CRS 显示时几何变形不做修正；标注为已知限制。
- **无金字塔格式(如非 tiled GeoTIFF)**：读实际数据需整行解码，比有金字塔慢。缓存先贴保证了交互即时；属可接受，V1 不异步分块。
- **缓存与实际替换不跳变**：两纹共用同一拉伸 min/max(缓存阶段即确定)，保证 1024→实际 无缝。

## 10. 测试与验收
- 单波段 `.tif`：拉伸显示灰度/伪彩，min/max 手动调整即时生效。
- 三波段 `.tif`：RGB 合成，R/G/B 可各自换波段且可重复(如 R=B)仍正常。
- HDF/NetCDF 多 subdataset：拖入弹选择框，勾选多个 → 多个栅格图层。
- 与矢量混布：栅格铺底、矢量叠加、显隐/顺序正确。
- 命令行 `<file>` 打开栅格文件能直接显示。
