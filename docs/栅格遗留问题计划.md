# 栅格遗留问题计划

> 对齐日期：2026-11-25。本文只列计划，不代表已经实现。
> **实现状态：R1–R12、R14–R16 已实现；R13 按计划保留当前四角重投影方案。**
> 目标：在“轻量浏览、以渲染观感为准”的定位下，修复稳定性问题，再补齐影响实际使用的栅格能力。

## 当前基线

已完成：

- 单/多子数据集加载；
- 灰度拉伸、预设伪彩色、RGB；
- 最长边 1024 底图 + 大图 256×256 细节块；
- 无 GeoTransform 影像按像素坐标显示；
- 跨 CRS 四角重投影后绘制；
- 栅格设置、显隐、缩放到图层。

---

## P0：正确性与稳定性

### R1. 修复细节块在途状态生命周期

**问题**：`blockInflight` 只插入不删除。块被 LRU 淘汰或读取失败后，再次进入视口不会重新请求。

**计划**：

- 块成功上传后删除在途标记；
- 块读取失败后删除在途标记，并允许有限重试；
- 卸载图层时清理该图层对应的在途标记。

**验收**：反复平移离开再返回，细节块能重新加载；失败块不会永久占住请求键。

### R2. 修复多栅格图层删除后的句柄错位

**问题**：删除中间栅格层后，`backend.rasters` 下标前移，但其余图层的 `rasterHandle` 未更新。

**计划**：

- 删除栅格层后同步修正所有剩余栅格句柄；
- 或改为稳定 ID/句柄，不依赖向量下标。

**验收**：加载 3 个以上栅格，删除中间层后其余图层纹理、细节块、设置重载均正常。

### R3. 统一栅格异步任务的作废机制

**问题**：清空/卸载时，待处理底图任务、在途细节块、rebase 结果没有完整作废，旧结果可能回填。

**计划**：

- 为底图和细节块任务引入统一 generation；
- 清空/卸载时递增 generation，并清空队列与在途集合；
- 消费结果时同时校验 generation 和图层身份。

**验收**：加载中清空、加载中卸载、设置重载中切换图层，都不会出现旧图层回填或重新出现。

### R4. 补齐栅格加载失败反馈

**问题**：元数据读取或底图组装失败时没有错误事件，界面缺少明确提示。

**计划**：后台返回成功/失败原因，主线程更新状态栏；失败时不保留半成品图层。

**验收**：损坏文件、缺失子数据集、无权限文件均给出可读错误。

## P1：实际使用缺口

### R5. 修正 1025–2048 像素影像的清晰度空档

**问题**：底图被限制到最长边 1024，而细节块要求 `maxDim > 2048`，中间尺寸放大后没有全精度来源。

**计划**：

- `maxDim <= 2048` 时按原始精度上传底图；
- 或把细节块启用阈值降到 1024。

**验收**：1500×2000 左右影像在全幅和放大后均无异常模糊。

### R6. 支持旋转/斜切 GeoTransform

**问题**：底图按重投影后的轴对齐包围盒绘制；细节块视口反算忽略 `geo[2]/geo[4]`。

**计划**：

- 底图和细节块使用完整仿射四角，而非 bbox；
- 视口反算使用完整 2×2 仿射逆矩阵；
- LOD 像素尺寸考虑旋转/斜切影响。

**验收**：旋转矩形栅格的位置、方向、细节块边界均正确。

### R7. 正确默认波段与 Alpha 处理

**问题**：四波段影像默认固定 1/2/3，不跳过 Alpha，也没有 A/IR/R/G 自然色排序。

**计划**：

- 元数据保存颜色解释；
- 默认 RGB 选择前三个非 Alpha 波段；
- 对常见四波段组合给出自然色默认顺序。

**验收**：RGBA 与 A/IR/R/G 测试影像首次打开颜色正确。

### R8. 真正使用 Palette 颜色表

**问题**：只识别 `isColorTable`，伪彩色仍使用内置渐变。

**计划**：读取 GDAL Color Table；有调色板时默认伪彩色并直接映射，无调色板时使用预设渐变。

**验收**：Palette TIFF 的颜色与 GDAL 一致。

### R9. Gamma 与 NoData 透明

**问题**：UI 有 Gamma，但渲染未使用；`clipNoData` 未实现，Alpha 恒为 255。

**计划**：

- Gamma 同时作用于底图和细节块；
- 元数据读取 NoData；
- 开启透明时按 NoData 输出 Alpha=0。

**验收**：底图与细节块叠加无跳变，NoData 区域正确透明。

### R10. 文件类型识别增加 GDAL 兜底

**问题**：当前只按扩展名分派，特殊扩展名的栅格可能走矢量分支。

**计划**：扩展名失败时用 `GDALIdentifyDriverEx()` 或试开 `GDAL_OF_RASTER`。

**验收**：无扩展名/冷门扩展名栅格仍能正确加载。

## P2：定位与高级能力

### R11. 无配准影像与地理图层混布

**问题**：像素坐标与地理坐标一起参与全幅适配，尺度冲突。

**计划**：明确“像素坐标系图层”与地理图层不能叠加；混布时提示，并避免用混合 bbox 自动适配。

**验收**：混布时至少一个坐标系明确不可叠加，另一图层仍保持可用视野。

### R12. RPC 元数据读取与展示

**问题**：需求中的 RPC 读取、UI 展示、角点定位尚未实现。

**计划**：

- 读取 GDAL `RPC` metadata domain；
- 图层信息展示“含 RPC”；
- 计算四角经纬度，作为无 GeoTransform 时的简化定位。

**验收**：含 RPC 的影像能展示元数据，并按角点范围放置。

### R13. 跨 CRS 绘制精度

**问题**：当前只重投影四角后取 bbox，大范围/高纬度影像会变形。

**计划**：优先保留当前方案；若实际出现明显错位，再引入 GDAL Warp/VRT 或网格重投影缓存。

**验收**：典型跨投影带影像在可接受范围内对齐；不做逐像素高成本 warp 作为默认路径。

### R14. 子数据集元数据预读

**问题**：目前只枚举子数据集名称，不预读尺寸和波段。

**计划**：选择对话框显示每个子数据集的尺寸、波段数和 CRS。

**验收**：HDF/NetCDF 多子集列表可直接分辨数据变量。

## 明确不做

- 不做全局拓扑重建；
- 不做磁盘 warp、全分辨率预览、地理配准编辑器；
- 不把“完全准确”作为渲染目标；
- 跨瓦片孔洞保持当前近似方案，除非实际画面出现明显问题。
