# 需求分析（peekGIS）

> 版本：v0.1（草案，已根据评审决策更新）
> 目标：用 ImGui / GDAL / OpenGL VBO 等开源库，做一个**高效浏览 GIS 数据**的小型系统，
> 能在 **Win64 / Linux-x64 / 麒麟 aarch64（Linux ARM 桌面）** 上运行。
> 注：百万级矢量主层采用 **OpenGL VBO 直接绘制**；thorvg 暂不入 MVP（后续可选点缀层）。

---

## 1. 项目背景与目标

用户需要在一个轻量、跨平台的小型系统中**快速浏览** GIS 数据，重点是：

- **矢量为主**（线/面，单图层可达 ~100 万要素），能“打开就看整幅”，平移缩放流畅。
- **栅格为辅**（~1 万像素量级的卫片，含 RPC 元数据，能读能显示即可）。
- 渲染要快，允许用缓存、后台多线程、分块等手段。
- 系统要小、依赖精简、构建简单（用 xmake）。

---

## 2. 运行平台

| 平台 | 架构 | 说明 |
|------|------|------|
| Windows | x64 | MSVC 或 MinGW-w64 |
| Linux | x64 | 桌面发行版 |
| 麒麟 Kylin | aarch64 | 国产 Linux ARM **桌面版**（非嵌入式），用桌面 OpenGL |

图形后端统一选 **OpenGL 3.3 Core / OpenGL ES 3**（三平台均可）。
窗口/输入用 **GLFW**（三平台支持好）。

---

## 3. 功能需求（FR）

- **FR1 数据加载**
  - 矢量：Shapefile、ESRI FileGDB（只读，用 GDAL 内置 OpenFileGDB 驱动）、GeoPackage（GPKG），以及 GDAL/OGR 支持的其他矢量格式。
  - 栅格：常见卫片格式（GTiff 等），量级约 1 万像素；能读取其中的 **RPC 元数据**并在 UI 展示/用于定位。
- **FR2 地图浏览**
  - 打开后默认显示**全幅（整幅矢量）**。
  - 支持平移、缩放（滚轮/拖拽）、复位全幅。
  - 交互流畅（目标见 NFR1）。
- **FR3 图层管理（左栏）**
  - 左sidebar 以图层树形式展示已加载图层。
  - 支持：显隐切换、图层顺序调整、显示图层 CRS / 要素数等基本信息。
  - （可选）透明度调节、按属性简单分类着色开关。
- **FR4 投影与动态重投影**
  - 系统有统一的**显示 CRS**（display CRS）。
  - 不同源 CRS 的图层在显示时**对齐到显示 CRS**。
  - 支持用户在运行时**切换显示 CRS**，切换后各图层重新对齐（动态重投影，见总体/详细设计）。
- **FR5 几何缓存**
  - 矢量图层首次打开后，将其几何构建结果序列化到磁盘（`.geomcache`），重开时跳过 OGR 解析、毫秒级载入。
  - 源文件变更（mtime/size 变化）时缓存自动失效重建。
- **FR6 状态栏坐标**
  - 底部 statusbar 实时显示鼠标在地图中的坐标（显示 CRS 坐标；可同时显示源 CRS 坐标）。
- **FR7 跨平台一致**
  - 同一套代码、同一构建系统（xmake）在三平台产出可执行文件，行为一致。

---

## 4. 非功能需求（NFR）

- **NFR1 性能**
  - 100 万线/面要素：首次打开（含读取+建缓冲+投影）控制在**数秒**内；重开（命中缓存）**亚秒级**。
  - 平移/缩放渲染目标 **30–60 fps**（GPU 绘制 VBO，仅改变换矩阵）。
- **NFR2 资源占用**
  - 内存可控：不在内存中长期保留全量 OGR 要素对象；VBO 顶点数据为主。
  - 缓存体积可控：单图层缓存为紧凑二进制，存放于 `<exe目录>/cache`；支持 **LRU 淘汰**，上限在配置界面/TOML 中设置。
- **NFR5 字体与高 DPI**
  - 内置 **霞鹜新晰黑** 字体，通过 ImGui FreeType 加载。
  - 适配高 DPI（麒麟/Win 常见）：字体尺寸按 `DisplayFramebufferScale` 缩放，UI 布局随 DPI 调整。
- **NFR3 可移植与构建**
  - 单一构建系统 **xmake**；三平台用统一 `xmake.lua`，交叉/原生均可。
- **NFR4 简易**
  - 系统要“小”：架构清晰、模块少、依赖精简，不做复杂 GIS 编辑/分析。

## 5. 约束与依赖

| 用途 | 库 | 说明 |
|------|----|------|
| 窗口/输入/GL 上下文 | GLFW | 三平台统一 |
| GL 函数加载 | glad（GL 3.3 core） | xmake 引入 |
| 界面 | Dear ImGui（**docking 分支** + FreeType） | 左栏+地图+状态栏；加载 ttf 字体 |
| 字体 | 霞鹜新晰黑（LXGW，ttf/otf，内置） | 高 DPI 适配（见 NFR 补充） |
| 地理数据读取 | GDAL / OGR | 矢量+栅格+RPC+OpenFileGDB |
| 投影 | PROJ（随 GDAL） | 动态重投影 |
| 主矢量渲染 | **OpenGL VBO** | 百万要素主渲染器（非 thorvg） |
| 配置 | TOML（toml11） | 缓存 LRU 上限等可配置项 |
| 数学 | glm | 矩阵/变换 |
| 日志 | spdlog | — |
| 缓存压缩 | zstd（可选，后续） | 落盘压缩 |

> 说明：百万级线/面主层采用 **VBO 直接绘制**，而非用 thorvg 为每个要素建场景对象
> （thorvg 建 100 万个 `Shape` 对象内存与构建成本过高，且每帧重绘贵）。
> thorvg **暂不入 MVP**，后续如需“选中高亮/标注/图例”等少量精美矢量再引入。
> 缓存管理改用 **文件 + TOML 配置**（弃用 sqlite3），保持依赖精简。

## 6. 范围外（暂不实现）

- 矢量/栅格数据编辑、属性编辑。
- 复杂空间分析、拓扑运算。
- 3D 地形/倾斜摄影。
- 服务端/Web 发布。
- 栅格正射纠正（RPC 仅读取+定位展示，严格正射为后续增强）。

## 7. 评审决策记录（已确认）

1. **默认显示 CRS**：首次打开用**数据自身的 CRS**；若数据无 CRS，则回退 **EPSG:4326**。
2. **动态重投影**：通过**显示界面（下拉/按钮）切换显示 CRS** 触发，切换后各图层重新对齐（显式触发，非连续）。
3. **缓存位置**：`<可执行文件目录>/cache/`。
4. **LRU 上限**：支持设置，提供**配置界面**，配置存为 **TOML** 文件（含磁盘缓存容量上限与淘汰策略）。
5. **字体与 DPI**：使用 **霞鹜新晰黑**，需 **DPI 适配**（FreeType 加载 + 按帧缓冲缩放调字号）。
6. **thorvg**：**MVP 暂不加入**，后续可选做点缀层。
7. **栅格 RPC 定位**：需要**精确的位置显示**；若实现成本高，允许先做“类似动态重投影”的简化处理（按 RPC 计算角点地理坐标并据此放置/显示）。
