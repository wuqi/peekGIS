# peekGIS 超大型矢量数据渲染方案 v2 · 详细实现设计（纯渲染版）

> 制定日期：2026-09-11。
> 基准分支 `8c44730`（纯矢量缓存）。目标：广东 GDB（千万级面），测试：台湾 shp（1080 万段）。
> **前提（本次重排核心）**：缓存**只服务于渲染**。任何拓扑/属性/精度语义一概不维护、不保证，**只要画面看起来对**。
> 因此所有"纯视觉细节"（跨瓦片环拼接、方向、孔顺序、格点精差）都不再是设计约束，一切以求简、快、够看为准。

## 1. 基准代码事实（读 8c44730 确认，勿臆测）

- AsyncLoader（src/data/async_loader.*）输出**已耳切三角形**的 flat 顶点数组（verts/pts/tris），chunk 按要素数/顶点数切、无空间语义 → **v2 不复用，新写要素环流读取器**（不破坏现有 loader）。
- GLBackend 已有 `RasterTile tex+quad` 视口 LRU 模板（tplVao 每帧填四边形 + setRasterTile/hasRasterTile/clearRasterTiles）→ **v2 瓦片渲染沿用这套 LRU 节奏**。
- MapScene / App 现有帧循环：`applyLoaderEvents()` 消费 chunk、`backend.render(scene)` 画 FBO；几何用 `vector_reader`（gdalOpenVector / VectorData / reprojectVertices / computeExtent）。

## 2. 数据模型（纯渲染，能画就行）

金字塔 8 层：**L0=1 瓦片(全图 512 格)**，**L7=128×128 瓦片 × 512 格**（全图 65536×65536 格）。

```
VtTile（内存/盘中形态一致）:
  originX, originY : double     // 瓦片左下角，显示CRS
  epsg             : i32        // 该缓存集建立时的显示CRS(未定时=源EPSG)
  vertexCount      : u32
  verts            : int16 x,y × vertexCount   // 瓦片内相对坐标, 净区 0..512, 扩边区可 -10..522
  ringCount        : u32
  rings            : {type:u8(0线/1面/2点), firstVertex, vertexCount} × ringCount
  polyToRing       : u32 × (面环分组)          // 面=外环+孔环一组, 供 earcut 输入
```
要点：**存环不存三角**（渲染时才 earcut）；顶点流在构建期按"边收边 append 并在 append 时写回 ring.firstVertex"——偏移天然正确，不做"建完再删点重排"。

### 扩边裁切 + 渲染裁外围（本版核心，与矢量瓦片 pbf 同一原则）
- **构建期统一按"瓦片 + 扩边 10 格"裁切**（窗口 = 0..512 向外扩 10 格 = [-10..522]），面/线/点一律用扩边窗口——与 pbf 一致，不区分元素类型。
- **渲染期把外围 10 格裁掉，每瓦片只显示自己 0..512 净区**。等价的干净实现（视觉结果一致）：
  - **面（fill）**：构建裁到扩边窗口后，**提交 VBO 前把顶点 clamp 到 0..512**（在瓦片边界切成直线）→ 邻瓦片同色拼缝、**fill 零重叠 → 无 alpha 叠加痕**；
  - **线/点**：整条含扩边画（不 clamp，可在 -10..522 范围内）→ 边界处与邻瓦片同一份几何重叠、不透明无痕 → 用这份重叠补上量化误差造成的接缝；
- fill 净区 = 0..512，线/点允许 -10..522；同一瓦片顶点流统一存储，渲染时按 ring.type 决定 clamp 与否。
- 投影连续性问题（跨瓦片接不上）**:先按此方案实现实测，若出现错位再接缝手段上调整，不提前过度设计。**

## 3. 构建管道（自底向上，扫源一遍定网格 + L7 驻内存 + 内存合并边合边落盘）

### 前置：整层 bbox
构建网格前需要层范围：`OGR_L_GetExtent` 先取（shp/gdb 毫秒级）；取不到的格式退化**两遍扫描**（第一遍算范围、第二遍构建）——明确写入兜底，否则无范围格式无网格可建。**显示 CRS ≠ 源 CRS 时，对 GetExtent 四角重投影取包络作为显示 CRS bbox（大概够用，格化后误差可接受）**。显示 CRS 未定（单文件打开）时，**用源 EPSG 当网格基准**写入缓存键。

### 阶段 A —— L7 构建（不流式：先定网格 → 选择要素逐瓦片裁切 → L7 全内存驻留）

**构建策略（决策）**：不考虑流式读取。先算好整层 bbox 定死网格 → 逐要素选择、裁切、生成，**L7 全部 16384 个瓦片直接驻内存**，构建期不写盘不换出；全部完成后批量落 mdbx，内存留着供阶段 B 合并（内存预算见 §9）。

1. 逐要素（GDAL GetNextFeature）→ 源 CRS 环；源≠显示时整环一次性 `reprojectVertices` 到显示 CRS。
2. 瓦片归属：要素（环）bbox 与 L7 瓦片矩形求交 → **得到瓦片 ID 集合（通常 1~4 个；大环如省界/大湖跨几十~上百个瓦片，两者都合法，逐个裁剪写入即可）**。对集合中每个瓦片**按类型裁剪**：
   - 面环：Sutherland–Hodgman 裁到 [瓦片净区＋10格扩边] 窗口（凸窗口裁剪不会分裂成多片，输出单环；孔环另裁，polyToRing 分组保留）；
   - 线：每段与窗口求交（线裁剪，不套面算法）；
   - 点：落哪归哪；
   - 裁剪结果为空的片段 → 丢弃。
3. 顶点量化：`int16 = round((x - tile.originX) / tileTw * 512)`，扩边区允许 **-10..522**。
4. **环内连续点去重**：仅同一环内相邻两格点重合时删后者（末点与首点同格时以"末点强制=首点"闭合，供 earcut），**不跨环 / 不跨要素合并**。去重后 **环顶点 <3 或面积≈0 → 丢弃**（量化后视觉上本就消失，防 earcut 崩溃）。
5. 全部要素处理完 → **L7 批量写 mdbx（一次事务/批量）→ 提交即全层可用**；内存保留供阶段 B。

### 阶段 B —— 逐层栅格合并 L7→L0（L7 驻内存，直接内存合并，边合边落盘）
1. level 6..0：父瓦片 P = 4 子瓦片 A0..A3 **净区**并集（扩边区不参与合并，避免 4 重累赘）。**父层瓦片本身不再有扩边数据（顶点 0..512）**——跨父瓦片接缝靠量化端点相邻 ≤1 格（父格边长为子格 2×，容差更大）；L0 是整层单瓦片，无邻片，无需扩边。
2. 顶点子→父映射：先算**父全局格** `pg = round((子瓦片局部格 + 子瓦片起点全局格) / 2)`（**四舍五入，不用向零**，子扩边坐标为负时同样正确）；再减父瓦片起点全局格得**父瓦片内坐标** `px = pg - 父瓦片起点全局格`，结果 0..512。
3. 环段继承：每个子瓦片的环逐条保留为独立段（id/顺序不变），**不拼接跨边环**（视觉连续靠相邻格 ≤1 差分，见 §"看起来对"准则）。fill 只在各子净区内、同色，父拼缝天然连续。**合并时同样做环内连续去重 + 退化环丢弃（顶点<3/面积≈0）**；**点要素单独映射保留（不并入面环去重），同格多点不合并（GL_POINTS 同色同心，无视觉差）**。
4. 每父瓦片完成后单瓦片原子写 mdbx（依次做完全部 level）；L0 最后成型，写完更新 `fullyBuiltLevels`。

**"看起来对"准则（全部视觉相关，非拓扑）**：
- 跨瓦片断裂：线靠扩边 + 邻片重叠；fill 靠同色到边界。量化 ≤1 格误差视为连续。
- 合并后 4 段独立画：端点相邻 ≤1 格 → 渲染是连续直线，不看出拼接。
- 允许的细小伪影（写入验收"可接受"项）：10 格扩边内线/点重叠的线宽加粗（不透明无 alpha 痕）；L0 大面边界格化阶梯状。

## 4. 存储：mdbx KV + 单瓦片 zstd（替代 16×16 组块）

- 路径：`cache/vtk/<源hash8>_e<源EPSG>_d<显示EPSG>/tiles.mdbx`（目录即缓存集，删除缓存=删目录，备份=抄目录）。
- **数据库结构**：
  - 主库 `tiles`：`key = L<level>_<tx>_<ty>`（int 编码），`value = 单瓦片 zstd 压缩字节`（含 VtTile 头+顶点流+环段表）。
  - `meta`：整层 bbox、tileSize=512、pad=10、源hash/源EPSG/显示EPSG、构建时间戳、`fullyBuiltLevels`（每层完成标志）。
- **写入**：构建线程瓦片 ready 即单条事务 put → 原子可见；层全量完成额外写 `fullyBuiltLevels`。
- **读取**：渲染线程按瓦片 key 直达单瓦片 → zstd 解压（瓦片级小 frame，解压快），避免整块解压浪费。
- **大小权衡（结论）**：组块把 256 瓦片压一个 frame，重复扩边区只压一次；单瓦片压缩每瓦片十余格重叠数据各压一份 → **净数据约 +5~15%**，另加 mdbx 页存储开销（数据页为主，非纯 overhead）——相对 0.2~0.4GB 总量可忽略。收益远大于成本：免偏移表、免整块解压、随机读直达、原子写免"完成位图"、跨进程无锁竞争（本应用单进程）。
- **依赖**：mdbx 走 vcpkg（`d:\dev\vcpkg` 已由 xmake 默认指向），Step 0 引入。
- 键 = (源hash, 源EPSG, 显示EPSG, 构建时间戳)；源 mtime/size 变化 → 新键（旧缓存目录冷淘汰）。
- 显示 CRS 未定（单文件打开）时：用源 EPSG 建网格并写入 meta。

## 6. 线程与帧循环（2 个后台线程）

```
后台1 vt_build（单线程）: RingSink→L7(全内存→批量落 mdbx)→内存逐层合并→fullyBuiltLevels(meta)
后台2 vt_fetch（单线程）: 主线程查询队列{layer,level,tx,ty} → getTile(单瓦片zstd解压) →
                           CPU 将 int16 映射 float + earcut 面三角化 → 回传主线程队列

主线程每帧:
  applyLoaderEvents()（保持处理原有 loading/meta/完成，但与 v2 图层解耦）
  收 vt 构建事件(meta 更新) → syncVtView 的 hasVtTile/层可用性判定依据
  syncVtView(scene,i)   // chooseLevel(scale,bbox,已建层表) → 视口命中瓦片 → 缺片入队 vt_fetch
                        // 缺片垫底: 该层还没建/该瓦片还没写入 → 用已建可用的最高层瓦片放大
                        // mdbx 原子写保证读不到半块, 无需额外完成位图
  pollVtTiles()         // 收 fetch 结果 → VBO 上传
  backend.render(scene) // LRU 绘制命中瓦片

图层路由: 要素数 > 阈值(如300万) 自动 v2；否则保持原矢量缓存路径(v1.0)。阈值可配。
CRS 切换: displayEpsg 变化 → 键不匹配 → 廉价重建(§7)。
```

### 首屏（决策定稿）
- **首开默认 = 局部视口**（不 fit 全图）：fit 到数据 bbox 中心、缩放到"视口覆盖的 L7 瓦片数 ≤ 容限（≈64）"的尺度（约 3~5 个瓦片宽）→ 保证 L7 渐进绘制能直接填满视口。
- **加载即所见**：L7 随构建逐瓦片生成、逐瓦片贴上 → 用户立刻看到地图在眼前长出，不白屏、不空等；状态栏/角落显示"生成缓存 xxx 瓦片 / xx%"。
- **滚轮缩放**：从首开视口缩小 → 低层未建时用"已建最高层瓦片放大垫底"（模糊摊开）；继续缩到 L0 建好自动清晰。放大则在 L7 已建部分内正常选择。
- **L0 完成**：全层就绪，任意缩放走正常 chooseLevel。
- 为什么首开不 fit 全图：全图视口覆盖全部 16384 个 L7 瓦片，远超容限，L7 无法当垫底；只有缩到局部才符合"L7 随生成随绘制"。用户随时可自行缩小看全貌（等低层）。

## 7. 跨 CRS 重建（仅视口）
瓦片只存"显示 CRS 下 origin+int16"。显示 EPSG 变化时：
- **仅重建当前视口命中的瓦片**：读出旧瓦片 → 把（origin + int16/512×范围）还原的坐标用现有 `reprojectPoint` 逐点转新显示 CRS → 按新瓦片范围重量化 int16 → 写进新键路径；**秒级**（视口瓦片数 ≤ 容限，顶点量极少）。
- 其余层/瓦片不改，滚到哪按需重建；旧路径仍保留显示，待全部视口层完成后再整体清理。
- 重建期间过渡：新瓦片就绪前用原旧瓦片直接显示（视觉近似，可接受）。

## 8. 已知风险与预留调整手段
- **L7 全内存占用**：16384 瓦片 × 平均顶点数 × 2B 顶点 + 环表。台湾实测修正预算（预期 0.3~1GB），超标则对顶点数异常大的瓦片单独处理（换出策略兜底，但不预设）。
- **跨瓦片投影接缝**：显示 EPSG ≠ 源 EPSG 时重投影，瓦片边界处两侧几何量化后可能错位（≤1 格预期，异常时跨片差几格）。**先按扩边+重叠实现实测**；`PEEK_TEST_ZOOM` 类测试钩子观察；若错位明显，扩边从 10 格加大到 16/32 或对跨瓦片环做统一端点对齐（后补，不提前做）。
- **KV 体积**：单瓦片 zstd 比组块约大 5~15%，Step 7 实测记录，超标（>1.5×）再回组块方案——保留决策。
- **半透明 fill 的 alpha 叠加**：扩边重叠已在渲染期靠 clamp 净区消除；若实测仍有边界色痕，在 vt_render 提交阶段强制边界取整。

## 9. 预算（锚点，Step 7 实测修正）
广东千万面、平均面 8~16 顶点、zstd：
- 盘：~0.2~0.4GB（int16 4B/顶点、环存、层间去重）+ KV 单瓦片压缩约 +5~15%；单目录 `tiles.mdbx`。
- 内存：构建期 **L7 全驻 ~0.3~1GB**（16384 瓦片，台湾/广东实测修正）+ 阶段B 当前级；渲染期 VBO LRU ≤256 瓦片。
- 首开构建：扫源 1 遍（分钟级）＋逐层盘上合并（分钟级）。
- 缩放帧率：L0..L3 视口顶点 < 百万 → 60fps 有余（对比无 LOD 矢量缓存 2.4~4.2 亿三角/帧 → 1~5fps）。

- **Step 2 要素环流**：vt_source。单测：台湾读 10 万要素，类别计数、面环闭合、fid 一致。验收：绿+速度记录。

- **Step 4 层间合并**：vt_build 阶段B。单测：手工 2×2 子→父、跨边环不拼但端点相邻、顶点递减。验收（台湾）：L0..L6 齐全、递减曲线、L0 大小可控。
- **Step 5 矢量直绘**：vt_render + gl_backend 少量扩展。单测：面 clamp 净区规则/线扩边剔除/耳切输入构造可测。验收（台湾）：缩放至 L7 无缝无线头、切换垫底无爆闪、帧率记录。
- **Step 6 首屏/复用/CRS**：App 接线——首开局部视口（fit 数据中心、视口瓦片数 ≤ 容限）+ L7 随生成随贴；滚轮缩小垫底规则；L0 完成后全图可用；二次打开先贴 L0；跨 CRS 仅视口重建（origin 重投影+int16 重量化）。验收：首开局部 L7 渐进可见、缩放垫底无爆闪/白屏；二次开即开即显；显示 EPSG 切换仅视口重建秒级生效；双文件跨 CRS 无垃圾范围。
