# peekGIS 矢量缓存与瓦片渲染方案（当前实现）

> 对齐日期：2026-11-25。本文描述当前代码的总体架构；文件格式、参数细节和排错以
> [`docs/矢量缓存.md`](矢量缓存.md) 为权威说明。
>
> **定位：缓存只服务于渲染。** 不维护拓扑、属性或测量精度语义，目标是“打开就看、缩放流畅、画面看起来对”。

---

## 1. 两套缓存

| | v1.0 几何缓存 | v2 矢量瓦片缓存 |
|---|---|---|
| 源码 | `src/data/geom_cache.*` | `src/vt/vt_*.{h,cpp}` |
| 落盘 | `cache/<sourceId>/{meta.bin,l0.bin,...}` | `cache/vtk/<hash8>_e<src>_d<dst>.vtk` |
| 载荷 | float32 描边 + 耳切三角形，各存一份 | int16 量化环，单份 + LOD |
| 空间划分 | 均匀网格分桶 | 四叉树瓦片 |
| 精度 | 源坐标无损 | 量化/抽稀，面向显示 |
| 适用 | 中小数据 | 大数据/超大数据 |

### 打开源文件时的路由

1. `.vtk` → 直接打开瓦片缓存。
2. 已有匹配 v2 缓存 → 优先使用 v2，不看数据规模。
3. 无缓存时估算顶点数：
   - `< [vt] threshold_verts` → v1.0；
   - `≥ threshold_verts` 且 `auto_build=true` → 后台构建 v2，边建边显示覆盖块。
4. 数据库连接串不参与 v2 自动探测。

## 2. v2 数据模型

- L0 为 1 个正方形瓦片，覆盖显示 CRS 下的数据范围。
- 第 L 层为 `4^L` 个瓦片。
- 粗层净区 512 格、扩边 10 格；最深层净区 1024 格、扩边 20 格。
- 顶点为瓦片内 int16 相对格坐标。
- 存环不存三角形：`VtRing` 保存线/面/点、孔环标记、顶点范围和 `polyGroup`。
- 面的外环与孔环共享 `polyGroup`，渲染时再耳切。
- 小于一格的碎面写入 `cover` 存在性栅格，避免丢弃后看着像缺数据。
- 顶点使用 delta + zigzag + varint，整片再 zstd 压缩。

### 扩边与 scissor

面、线、点统一裁到扩边窗口；渲染时按瓦片净区设置 `glScissor`。扩边几何照画，输出像素按净区裁掉，保证相邻瓦片共享边界、不重复叠加半透明 Alpha。

## 3. 构建管道

### 3.1 选最深层 Lmax

默认按数据的典型结构尺度选择：

1. 采样相邻点间距，取 p50；
2. `targetCell = p50 / target_error_factor`；
3. 取满足最深层格距不超过 `targetCell` 的最小层；
4. 受 `maxLevelCap`（默认 12）限制。

`target_error_factor=1.0` 为推荐值；越大越浅、越省空间，越小越深、越清晰。

兼容策略：`target_error_factor=0` 时退回旧的“每瓦片目标顶点数”策略，`target_verts` 只在该模式下使用。

### 3.2 层数配置的实际语义

- `levels >= 0`：**最深层上限**，仍自动估算，只把过深结果压浅；
- `levels = -1`：完全自动；
- `max_level`：兼容字段；App 仅在 `levels < 0` 时将其作为上限使用；
- CLI `--levels` 与 `--maxlevel` 当前都映射到上限语义；
- 内部 `forceLevel` 只用于测试/特殊调用，不是普通用户配置。

### 3.3 阶段 A：源路由

一次遍历源要素，每个环同时路由到所有保留层：

- `level_step=2` 表示隔层保留，并始终保留最深层；
- 按层抽稀 → 扩边裁剪 → 量化 → 环内同格去重；
- bbox 完全落在片内时跳过 GEOS 裁剪快路径；
- 内存瓦片按顶点数 LRU，超限落盘。

### 3.4 阶段 B：粗层合并与拓扑

- 默认只把 L0 由更细层合并生成；可用 `PEEK_VT_MERGE_TOP` 调整；
- 对保留的 `L < Lmax` 做拓扑后处理：小面并入邻面、按 arc 抽稀；
- 最深层不做后处理，保留碎面细节；
- 支持取消，各阶段定期检查取消位。

### 3.5 finalize

压实数据段中的孤儿块，写稀疏槽区和行目录，回填文件头并截断文件，标记已完成层。

## 4. 文件布局

```text
[184B VtFileHeader]
[数据段：各瓦片 zstd 块]
[稀疏槽区：只为实际用到的 tx 连续段分配 16B 槽]
[行目录：每个 (level, ty) 一条 16B 记录]
```

- 文件魔数 `PEEKVT01`，当前 `version=2`；
- `headerSize` 必须等于 `sizeof(VtFileHeader)=184`；
- 随机读先查行目录，再定位槽，复杂度为 O(log 行数)；
- 构建期同一实例可回退到内存槽表；跨实例只能读 finalize 后的文件；
- `reloadHeader()` 同时刷新文件头和行目录。

## 5. 渲染

### 5.1 正常模式

1. 根据当前缩放选择已建层；
2. 计算视口命中瓦片；
3. 后台读缓存、重投影、耳切；
4. 主线程上传 GPU VBO；
5. 按净区 scissor 绘制。

GPU 驻留瓦片按**数量 LRU**管理，每层默认最多 512 片。旧层瓦片在新层未就绪时作为垫底，避免闪屏。

### 5.2 构建期

后台每写一片，主线程立即请求并绘制；驻留上限按字节控制，默认 256MB。构建完成后切回正常选层模式。

### 5.3 跨 CRS

缓存烘焙在 `dstEpsg`。显示 CRS 不同时，worker 对整片顶点重投影后再上传；一份缓存可适配任意显示 CRS。切换 CRS 会清空当前驻留瓦片。

### 5.4 超 Lmax 直读

当视口期望层达到 `Lmax + raw_enter_margin`（默认 2，即再放大约 4 倍）时：

- 读取原始矢量源的当前可见区域；
- 不抽稀、不落盘，按 8ms 分片后台渐进产出；
- 有 CRS 且启用空间过滤时，大源文件（>2 万要素）需要快速空间索引，否则该会话禁用直读；
- `raw_budget_ms` 是**准入预算**，不是硬中断：进入后即使超时也会继续跑完并保留结果；
- 状态栏显示“原始数据”表示已进入直读。

## 6. 当前默认配置

```toml
[vt]
auto_build = true
threshold_verts = 10000000
level_step = 2
target_error_factor = 1.0
max_level = -1
levels = -1
target_verts = 2048
max_total_verts = 0       # 0=不限制
max_verts_per_tile = 0    # 0=不限制
raw_over_max = true
raw_budget_ms = 2000.0
raw_enter_margin = 2
```

体积安全阀默认关闭。需要限制体积时，可设置 `max_total_verts` 和 `max_verts_per_tile` 为正值。

## 7. 已知容忍与后续方向

当前刻意容忍：

- int16 量化误差和 L0 大面边界阶梯；
- 跨瓦片孔洞由 `polyGroup` 继承 + 每片耳切近似处理；
- 正常模式按瓦片数量而非字节做 GPU LRU；
- 存储使用 `std::fstream`，尚未切换 mmap；
- 直读缩放重试有 3% 节流。

后续可做：正常模式字节 LRU、mmap、更严格的跨片孔洞处理、按空间顺序构建。上述均不影响当前“以渲染观感为准”的定位。
