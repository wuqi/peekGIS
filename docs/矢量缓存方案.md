# peekGIS 超大型矢量数据渲染方案 v2 · 设计与实现（2026-09 对齐实现）

> 初版设计 2026-09-11；本文档已按**实际实现**修订。
> 基准分支 `8c44730`（纯矢量缓存）。目标：广东 GDB（千万级面）。
> **前提**：缓存**只服务于渲染**。不维护拓扑/属性/精度语义，**只要画面看起来对**。

### 已确认决策（留档）
| # | 决策 |
|---|---|
| 1 | 首开即见：打开大数据后台建缓存，**边建边把出来的瓦片画出来**（内存 LRU 淘汰）；建完切回按缩放选层的正常模式 |
| 2 | 顶点 int16 相对坐标（净区 0..512，扩边 -10..522），4B/顶点 |
| 3 | 扩边裁切统一（面/线/点同窗口 [-10..522]）；**渲染期按每片净区做 scissor 裁切**（见 §3.3） |
| 4 | 合并 = 降采样(÷2) + 环内连续去重 + **按层近共线抽稀**（不拼跨边环） |
| 5 | 512 网格 / int16 "大概够用"不复议 |
| 6 | 存储 = **自研单文件 + 每层固定槽表 + 单瓦片 zstd**（O(1) 随机读 / 无外部 DB / 结构自控） |
| 7 | 版本：`v1.0`=8c44730；开发分支 `vector-tile` |

## 0. 实现现状（与初版设计的关键偏差）

实现文件：
```
src/vt/vt_types.h          常量 + VtTile/VtRing + 文件头/槽表 + 序列化
src/vt/vt_cache.h/.cpp     单文件存储: 文件头 + 每层槽表 + 追加数据段(zstd) + 键/列目录
src/vt/vt_source.h/.cpp    GDAL 顺序要素环流(点/线/面, 可选重投影) + 顶点数估算
src/vt/vt_build.h/.cpp     L_max 估算 + 阶段A(裁剪/抽稀/量化/去重/LRU) + 阶段B(÷2合并)
src/vt/vt_geom.h           瓦片 -> float 几何(面按 polyGroup 聚合外环+孔后 earcut)
src/vt/vt_scissor.h        净区 -> 屏幕像素 scissor 矩形(纯函数, 可单测)
src/render/vt_render.h/.cpp VtRenderer: 选层 + 后台读/重投影/earcut + 主线程上传 + LRU + scissor
tools/vt_build.cpp         建缓存 CLI (--auto 写到 app 自动发现路径)
tools/vt_estimate.cpp      只读估算(要素数/顶点数/各层点数/L*/体积/路由建议)
tests/test_vt.cpp          存储往返/构建端到端/瓦片几何/scissor 单测
```

与初版设计的主要偏差：

1. **存储用 `std::fstream`，不是 mio mmap**。单文件布局与槽表一致；写追加 + 每片 `flush()`（构建期读端另一句柄才能看到）；`reloadHeader()` 刷新 `fullyBuiltLevels/dataEnd`。mmap 留作后续优化。
2. **`L_max` 用"格化点数"选层，不是 `ceil(log4(N/2048))`**。原公式用原始 N，会多切一层（实测广东多切 1 层）。实现改为：步进抽样、对每个候选层做**格化计数** `P(L)`（量化到该层格距 + 连续去重，与阶段A一致，非 Douglas-Peucker），取 `argmin |P(L)/4^L − target|`。cap 12。
3. **合并阶段增加"按层近共线抽稀"**。初版仅"÷2 降采样 + 连续去重"，实测**对细层几乎不降顶点**（源点间距大于格距），广东总体积 4.1× 源 → 3.6GB。加抽稀（容差 = 该层格距 × sfactor）后降到 1.68× → **1.71GB**。
4. **填充不用"顶点 clamp 净区"，改为"每片按净区做 `glScissor`"**（面/线/点统一）。扩边几何照画（保证边界覆盖），输出像素按净区裁掉 → 相邻瓦片**严格共享边界像素**（无缝、不重叠、不叠 alpha）。scissor 取整是纯函数 `tileScissorRect`，有回归测试。
5. **跨 CRS 用"运行时整片重投影"**：worker 里把瓦片顶点从缓存 CRS `reprojectVertices` 到显示 CRS（每片一次，结果进 VBO），不是"仅视口重建写新键文件"。一份缓存适配任意显示 CRS。
6. **自动分流按估算顶点数**（`[vt] threshold_verts`），不是"缓存体量 >200MB"；且**无缓存时后台自动建**（见 §5）。
7. **构建期渐进渲染**：build 线程每写一片 `onTile(level,tx,ty)` → 主线程 `requestTile` → 渲染（字节 LRU 256MB）。不是初版的"仅首屏局部视口"策略。
8. **缓存管理窗口同时管理 v1.0 几何缓存与 v2 瓦片缓存**。

## 1. 基准代码事实

- AsyncLoader（src/data/async_loader.*）输出**已耳切三角形**的 flat 顶点数组（verts/pts/tris），无空间语义 → v2 **不复用**，新写要素环流读取器（`vt_source`）。
- GLBackend 的矢量 program 用 `uCenter/uInv` 把世界坐标映射到 NDC；v2 复用该 program 直绘 float 顶点。
- v1.0 几何缓存（`GeomCache`，`cache/<sourceId>/`）继续作为**小/中数据**的默认路径。

## 2. 数据模型

金字塔层数自适应：L0 = 1 瓦片（全图 512 格），最深层 L_max 瓦片数 = 4^{L_max}，每瓦片 512 格。

**L_max 估算（实现）**：顺序步进抽样 ~2000 要素；对候选层 L=0..cap，格距 `cell_L = S/(512·2^L)`（S = 显示 CRS 正方形边长），对每个样本要素做**格化计数**（量化到 cell_L + 连续去重，面<3点/线<2点丢弃），得该层总点数估计 `P(L)=F×mean`；取 `argmin |P(L)/4^L − targetVerts|`。`targetVerts≈2048`、cap=12（可配）。

```
VtTile:
  originX, originY : double     // 瓦片净区左下角(显示 CRS)
  epsg             : i32
  vertexCount      : u32        // = verts.size()/2
  verts            : int16 x,y × vertexCount   // 净区 0..512, 扩边 -10..522
  rings            : {type:u8(0线/1面/2点), hole:u8, firstVertex:u32,
                      vertexCount:u32, polyGroup:u32} × ringCount
```
- **存环不存三角**（渲染时才 earcut）；`polyGroup` = 源多边形全局 id（外环+孔共享），供 earcut 聚合。
- 序列化：`[originX:8][originY:8][epsg:4][vc:4][rc:4][verts][rings:rc×16]`，整块 zstd。

### 2.1 构建期扩边裁切
- 面/线/点一律裁到 **[-10..522]** 窗口（面：Sutherland–Hodgman；线：Liang–Barsky 逐段；点：bbox 判定）。
- 面/线在裁剪前先做**按层近共线抽稀**（容差 = 该层格距 × `sfactor`，默认 1.0）。

### 2.2 渲染期 scissor（核心）
- 每片瓦片绘制前，按其**净区(0..512)**在屏幕上的矩形设 `glScissor`（`tileScissorRect`）。
- 扩边几何照常提交（保证边界处一定覆盖），**输出像素被裁掉** → 相邻瓦片净区**严格共享边界像素**：无缝、不重叠、半透明面不叠 alpha。
- 边界用同一世界格线映射并同样 `lround` 取整，故左右/上下相邻瓦片的边界像素坐标相等（有单测保证）。

## 3. 构建管道

### 前置：层范围
`OGR_L_GetExtent` 取源范围（shp/gdb 毫秒级）；显示 CRS ≠ 源 CRS 时对**四角+中心**重投影取包络并加 2% 余量作为显示 bbox。显示 CRS 未定时用源 EPSG。

### 阶段 A —— 最深层 L_max
1. 逐要素 `GetNextFeature` → 环；源≠显示时用 OCT 整环重投影到显示 CRS。
2. 环 bbox → 相交的 L_max 瓦片集合；对每片：
   - **抽稀**（容差 = cell × sfactor）→ **裁剪到 [-10..522]** → 量化 `int16=round((v-origin)/cell)`；
   - 环内连续同格去重；面顶点<3 / 面积≈0 丢弃（防 earcut 崩）。
3. 内存瓦片 LRU：按**顶点数**上限（默认 2000 万）淘汰，淘汰即写盘（§4）。
4. 全部要素处理完 → 剩余内存瓦片落盘 → `fullyBuiltLevels` 置 L_max。

### 阶段 B —— 层间合并（父 = 4×4 子，÷2）
1. 父窗口在子格下覆盖 3×3~4×4 个子瓦片；逐个从存储读回。
2. 子瓦片 int16 → 显示坐标（`子origin + 局部格×子cell`）→ **抽稀**（容差 = 父格距 × sfactor）→ 裁到父窗口 → 量化到父格 → 环内去重 / 退化丢弃。
3. 环段独立保留（`polyGroup` 继承）；点单独映射。
4. 每父瓦片写完写盘；逐层 `setFullyBuilt`，直到 L0。

> 抽稀是**实测必需**：仅 ÷2 降采样时，细层每层近乎全量重存，总放大 4.1×；加抽稀后 1.68×。

## 4. 存储（单文件 + 固定槽表 + 单瓦片 zstd）

- 路径：`cache/vtk/<hash8>_e<源EPSG>_d<显示EPSG>.vtk`。`hash = FNV-1a(路径 + mtime + size)`（`/vsizip` 等不可 stat 时退化为路径 hash）。
- 布局：`[VtFileHeader][L0 槽表][L1 槽表]…[数据段]`
  - 文件头（定长，`sizeof(VtFileHeader)`）：magic/ver、tileSize=512、pad=10、maxLevel、src/dst EPSG、显示 bbox、网格原点与 L0 边长、源 hash、构建时间、槽表起始、dataStart/dataEnd、fullyBuiltLevels。
  - 每层槽表：`4^level` 个定长槽 `{offset:u64, size:u32, valid:u8, pad[3]}`（16B）→ O(1) 随机访问。
  - 数据段：追加的 zstd 单瓦片块。
- 写：压缩块追加 → 回写槽 → **`flush()`**（构建期读端才可见）。崩溃丢槽 = 该片缺失（可重建，不做事务）。
- 读：槽定位 → 读压缩块 → `ZSTD_decompress` → 反序列化。
- `reloadHeader()`：读端刷新 `fullyBuiltLevels/dataEnd`。
- 缓存管理 API：`listVtCaches/deleteVtCache/clearVtCaches`（扫目录读文件头）。

## 5. 线程与帧循环

```
后台 vt_build(单线程, App 里): buildVtCache → 每写一片回调 onTile(level,tx,ty)
后台 vt_fetch(单线程, VtRenderer 内): 读存储 → int16→float → (可选)重投影 → earcut → 结果队列
主线程每帧:
  - 构建期: 挂上 vt 渲染层(占位场景图层已在构建开始时建好) → 把 onTile 队列里的片
            requestTile 投给 fetch → 上传 VBO → 绘制(字节 LRU 256MB 淘汰)
  - 构建完成: setBuilding(false) → reloadHeader → 切回"按缩放选层 + 视口取片"模式
  - 正常模式: chooseLevel(scale, 已建层) → 视口命中瓦片 → 缺片入队 → 上传 → scissor 绘制
```

### 图层路由（实现）
打开矢量源文件时：
1. 已有匹配 v2 缓存（先 `e<src>_d<显示>`，再 `e<src>_d<src>`）→ 直接瓦片渲染；
2. 否则 `estimateSourceVerts`（顺序取前 5 万要素的平均点数 × 要素数）：
   - `< [vt] threshold_verts` → v1.0（原始几何缓存）；
   - `≥` 且 `[vt] auto_build=true` → **后台建 v2**（边建边看，状态栏进度），完成后切正常模式。
3. 也可直接打开 `.vtk`。

配置（`config.toml`）：
```toml
[vt]
auto_build = true
threshold_verts = 10000000
```

### 跨 CRS（方案 b：运行时重投影）
- 瓦片烘焙在缓存 `dstEpsg`。渲染时若 `scene.displayEpsg != dstEpsg`，worker 对整片顶点 `reprojectVertices` 后再上传（每片一次，非每帧）。
- 显示 CRS 变化 → 清当前层已驻留瓦片，按新 CRS 重投。
- 场景 bbox 用 `applyDisplayCrs` 现成逻辑（vt 层的 `data.srcEpsg=缓存EPSG`、bbox=缓存 bbox）。

## 6. 预算与实测

实测（广东 DLTB：F=4,594,750；源顶点 430,912,141；平均 93.8 点/要素；最大单要素 143,160 点）：

| 版本 | L_max | 瓦片 | 存储顶点 | 磁盘 | 用时 |
|---|---|---|---|---|---|
| 仅格化（初版设计） | 9 | 103,596 | 17.8 亿 | **3.6 GB** | 620s |
| + 按层抽稀（实现） | 9 | 101,618 | 7.2 亿 | **1.71 GB** | 441s |

其它：`Line.gdb`（10M 源顶点）→ 10.5MB / 4s；`randPoint.gpkg`（52 万点）→ 10MB / 2s。
渲染：按视口只取当前层可见瓦片，后台异步；构建期字节 LRU 256MB、正常模式瓦片数 LRU 512。

> 初版预算（0.2~0.4GB）基于"千万面 × 8~16 点"的假设，与实际（4.3 亿点、平均 94 点）差约 10 倍；本文以实测为准。
